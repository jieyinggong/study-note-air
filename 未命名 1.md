# VM Deployment Setup Guide

## A. SSH access setup

Before your teammate can log in to the VM, they need to have their own SSH key pair and their public key must be added to the server.

### 1. Generate an SSH key pair on the local computer

Run this on the teammate’s own machine:

ssh-keygen

This generates:

- a private key kept on their local computer
    
- a public key that can be shared and added to the VM
    

### 2. Add the public key to the VM

Someone who already has access to the VM must add the teammate’s public key to:

~/.ssh/authorized_keys

### 3. Test SSH login

After the key is added, the teammate can test login with:

ssh -i <your-private-key> root@68.183.205.143

For example:

ssh -i ~/.ssh/my_vm_key root@68.183.205.143

# B. First-time deployment steps

These steps are for the first time setting up and deploying the project on the VM.

## 1. Install required software

After logging into the VM, install everything needed for deployment.

This typically includes:

- Docker
    
- Docker Compose
    
- Git
    
- any other required system packages
    

---

## 2. Check that the domain is connected to the VM

Use ping from your local machine or from another machine to verify that DNS is resolving correctly.

Example:

ping jieying.live

This checks whether your domain points to the correct server IP.

---

## 3. Log in to GitHub Container Registry

If you are pulling Docker images from ghcr.io, connect Docker to your GitHub account:

echo <your-github-token> | docker login ghcr.io -u <your-github-username> --password-stdin

Make sure:

- the token has permission to read packages
    
- the username is your GitHub username
    

---

## 4. Create the docker-compose.yml file

Open a new file on the VM:

nano docker-compose.yml

Paste in the Docker Compose configuration.

Important:

- make sure all backend environment variables are filled in correctly
    
- double-check secrets, database config, ports, and image names
    

After pasting, save and exit.

---

## 5. Pull the Docker images

Run:

docker-compose pull

This downloads the latest images defined in the Compose file.

---

## 6. Start the containers in detached mode

Run:

docker-compose up -d

This starts the services in the background.

---

## 7. Check that all containers are running

Run:

docker ps

Verify that all expected containers are up and healthy.

---

## 8. Run database migrations

Run the backend migration command:

docker-compose run backend npx sequelize-cli db:migrate --config /models/config.cjs

This applies the database schema changes.

---

## 9. Stop all containers

After migration, bring the services down:

docker-compose down

---

## 10. Start the application in foreground mode for checking logs

Run:

docker-compose up

This lets you watch the console output directly.

Check carefully for:

- backend startup errors
    
- database connection issues
    
- migration problems
    
- missing environment variables
    
- frontend or proxy errors
    

---

## 11. If everything works, restart in detached mode

Stop the foreground process, then run:

docker-compose down

docker-compose up -d

This leaves the application running in the background for normal use.
